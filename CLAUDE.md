# CLAUDE.md

Правила роботи над цим репо. Джерело задуму — `PLAN.md`, читай його перед будь-якою фазою.

## Що це

Монорепо покер-тренажера: `web/` (Vite + React + TS) і `api/` (FastAPI + SQLAlchemy 2 async + Postgres).
Файл `poker-trainer.html` у корені — **джерело істини для ігрової логіки**. Діапазони, побудова
спотів і критерії воріт переносяться з нього 1:1. Нічого не «покращувати» на ходу: якщо здається,
що діапазон неправильний — це окреме рішення, не частина міграції.

## Команди

```bash
# Postgres (обов'язково першим — api без нього не підніметься)
docker compose up -d
docker compose ps          # має бути (healthy)
docker compose down        # зупинити; -v щоб знести том з даними

# API (з api/)
uv sync                                        # встановити залежності
uv run uvicorn app.main:app --reload --port 8000
uv run pytest                                  # тести
uv run ruff check . && uv run ruff format .    # лінт + форматування
uv run alembic upgrade head                    # міграції
uv run alembic revision --autogenerate -m "..."

# Web (з web/)
npm install
npm run dev          # http://localhost:5173
npm test             # vitest run
npm run typecheck    # tsc -b --noEmit
npm run lint         # oxlint
npm run build
```

`uv` живе в `~/.local/bin`. Якщо команда не знаходиться — `export PATH="$HOME/.local/bin:$PATH"`.

## Архітектурні правила

1. **Сирі події, не агрегати.** Сервер зберігає кожну відповідь окремим рядком у `attempts`.
   Статистика, ворота, drill-пули — похідні, рахуються SQL-запитами. Жодних лічильників
   типу `byPos` у базі: побачив у моделі поле-лічильник — це помилка.
2. **Ігрова логіка живе на клієнті.** `web/src/engine/` — чистий синхронний TS: діапазони,
   `buildSpot`, перевірка правильності, критерії воріт. Сервер = auth + журнал + агрегації.
3. **`engine/` не імпортує React.** Взагалі нічого з React, zustand чи DOM. Це умова
   тестованості: engine покривається vitest без рендера.
4. **Offline-tolerant.** Відповіді пишуться в localStorage-чергу і синкаються батчами.
   Тренування має працювати без мережі; синк доганяє після відновлення.
5. **Ідемпотентність синку.** Кожна спроба несе `client_id` (uuid з клієнта).
   `POST /attempts/batch` робить `ON CONFLICT (user_id, client_id) DO NOTHING`.
   Повторно надісланий батч не має створювати дублів — це покрито тестом.

## Стиль

- **Python:** type hints скрізь, `ruff` + `ruff format`, рядок 100. Без абстракцій на виріст:
  роутер → сервіс-функція → запит. Ніяких репозиторіїв, unit-of-work і DI-контейнерів.
- **TypeScript:** `strict`, без `any`. Використовуй `unknown` + звуження, якщо тип невідомий.
- **Коментарі українською — норма.** Назви змінних, функцій, файлів, полів БД — англійською.
- **Секрети тільки з env.** `.env.example` тримати актуальним при кожній новій змінній.
- **Коміти:** `phase-N: короткий опис`.
- Не додавати залежність, якщо задача вирішується стандартною бібліотекою за ~20 рядків.

## Відхилення від PLAN.md (узгоджені)

| Що в плані | Що зробили | Чому |
|---|---|---|
| `attempts.raiser_pos` | `attempts.villain_pos` + `attempts.limpers` | Одного поля мало: для `vs3bet` контекст — позиція 3-бетора, для `iso` — кількість лімперів (від неї залежить, чи береться звужений діапазон `TIGHTER2`). Без цього drill не відтворює точний спот. |
| React 18 | React 19 | `npm create vite` дає 19; підстав фіксувати 18 немає. |
| passlib + bcrypt | `bcrypt` напряму | passlib 1.7.4 (2020) ламається на bcrypt ≥ 4.1. Прямий виклик `bcrypt.hashpw` — це 5 рядків без проміжного шару, що і так відповідає правилу «без зайвих абстракцій». |
| Python 3.12 | Python 3.12 через `uv python` | Системний Python — 3.13; uv тягне 3.12 окремо, щоб збігалося з Docker-образом. |
| CSS modules або tailwind (на розсуд) | Звичайний CSS, один `index.css` + локальні файли | Стилі переносяться 1:1 з HTML-референсу. Tailwind означав би переписування всіх правил і гарантований дрейф вигляду. |
| Postgres на 5432 | 5433 назовні | Щоб не конфліктувати з локально встановленим postgres. |

Якщо додаєш нове відхилення — вписуй сюди рядок з причиною, як вимагає `PLAN.md`.

## Пастки цього оточення

- У zsh користувача `cp` — аліас на `cursor`. У Bash-командах використовуй `/bin/cp`,
  інакше замість копіювання відкриється редактор, а команда поверне 0.
- Паралельні Bash-виклики ділять один шелл: `cd` з одного впливає на інший.
  Використовуй абсолютні шляхи.
