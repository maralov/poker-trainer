# Poker Trainer

Тренажер 9-max кешу у два етапи.

**Етап 1 · префлоп:** чотири сценарії (відкриття, ізоляція лімперів, проти
рейзу, проти 3-бету), drill по накопичених помилках, ворота до наступного етапу.

**Етап 2 · постфлоп:** роздача грається від флопу до шоудауну — з вердиктом і
поясненням після кожного рішення. Рука героя й руки опонентів беруться з тих
самих діапазонів, які тренує префлоп, тож спот на флопі справді міг виникнути
з розіграного префлопу. Дві лінії: герой-агресор (відкриття, ізоляція) і
герой-колер проти опену. Свої вкладки: тренування, схема рішень (усі матриці
в людському вигляді), статистика по вулицях і категоріях, розбір патернів
помилок із розгортанням будь-якої зіграної роздачі.

Веб-версія standalone-файла `poker-trainer.html` — з логіном через Google,
збереженням прогресу на сервері і синхронізацією між пристроями. Це PWA: тренажер
встановлюється на головний екран телефона без App Store і працює без мережі.

## Стек

| Шар | Технологія |
|---|---|
| Frontend | React 19 + Vite + TypeScript (strict) |
| State | zustand |
| Backend | Supabase: Postgres 17 + Auth + RLS (свого сервера немає) |
| Auth | Google OAuth |
| PWA | vite-plugin-pwa (Workbox): manifest, service worker, офлайн |
| Тести | vitest — юніт (engine, черга синку) та інтеграційні (RLS, синк) |

## Швидкий старт

Потрібні Docker і Node 22+.

```bash
git clone https://github.com/maralov/poker-trainer.git && cd poker-trainer
npm install

# 1. Локальний Supabase (перший запуск тягне образи, це довго)
npm run db:start

# 2. Змінні оточення
/bin/cp .env.example web/.env      # локальні ключі вже вписані

# 3. Веб
npm --prefix web install
npm --prefix web run dev           # http://localhost:5173
```

Тренуватись можна без входу — прогрес лежить локально, відповіді чекають у черзі.
Вхід через Google вмикає синхронізацію між пристроями.

**Локальний вхід через Google** вимагає реальних OAuth-ключів у `supabase/config.toml`.
Без них локально працює все, крім самої кнопки входу; логіку синку покривають
інтеграційні тести.

## На телефоні

Відкрий прод у браузері телефона і встанови тренажер на головний екран:

- **iPhone (Safari):** «Поділитися» → «На екран „Додому“».
- **Android (Chrome):** кнопка «Встановити» на плашці вгорі сторінки або в меню браузера.

Встановлений тренажер відкривається окремим вікном без вкладок і запускається без
мережі: service worker кешує файли застосунку, а відповіді, як і раніше, чекають
у черзі синку. Оновлення приходять самі: нову версію видно при наступному
відкритті.

На iPhone встановлений застосунок має окреме від Safari сховище. Прогрес, набраний
у Safari без входу, туди не переїде — увійди через Google, щоб він синхронізувався.

Dev-сервер service worker не реєструє. Щоб перевірити PWA локально, потрібна
продова збірка:

```bash
npm --prefix web run build
npm --prefix web run preview       # http://localhost:4173
```

Іконки генеруються з `web/public/favicon.svg`: `cd web && npx @vite-pwa/assets-generator`.
Рішення й причини — у [`docs/superpowers/specs/2026-11-10-pwa-design.md`](docs/superpowers/specs/2026-11-10-pwa-design.md).

## Тести

```bash
npm test          # engine, черга синку, компоненти — без Docker
npm run test:db   # RLS і наскрізний синк — потрібен запущений npm run db:start
```

Тести engine звіряються з еталоном, знятим із `poker-trainer.html`: склад усіх
діапазонів і 471 спот, згенерований референсною `preBuildSpot` під детермінованим
`Math.random`. Порт перевіряється проти оригіналу, а не проти чисел, вписаних
з голови — деталі в `web/src/engine/__fixtures__/README.md`.

Тести RLS перевіряють, що користувач не бачить чужих даних. Це не формальність:
anon-ключ публічний, і політики — єдине, що ізолює користувачів.

## Структура

```
poker-trainer/
├── PLAN.md               # початковий план (архітектура змінилась після Фази 1)
├── CLAUDE.md             # правила, архітектура, узгоджені відхилення
├── poker-trainer.html    # standalone-референс, джерело істини для ігрової логіки
├── supabase/
│   ├── migrations/       # схема, RLS, SQL-функції
│   └── tests/            # інтеграційні тести політик і синку
└── web/src/
    ├── engine/           # чиста ігрова логіка, без React і без мережі
    ├── api/              # клієнт Supabase, черга синку, серверний прогрес
    ├── store/            # zustand: прогрес, сесія тренування, auth
    ├── components/       # зокрема InstallBanner — плашка встановлення PWA
    └── pages/            # Етап 1: Train / Ranges / Stats / Review
                          # Етап 2: TrainPost / PostRules / PostStats / PostReview
```
