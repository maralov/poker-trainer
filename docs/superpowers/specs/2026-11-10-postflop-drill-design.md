# Drill по постфлоп-помилках

Спека Етапу 2 (`2026-08-11-postflop-stage-design.md`, §1) свідомо відклала drill
по постфлоп-помилках. Розбір показує патерни помилок, але відпрацювати їх
цілеспрямовано ніде — цикл «помилився → побачив → відпрацював» на постфлопі
не замкнений. Ця спека його замикає.

## 1. Затверджені продуктові рішення

| Питання | Рішення |
|---|---|
| Одиниця drill | Патерн розбору (`PostFixKey`, 15 штук). Карти щоразу нові: вчиться правило, а не картинка |
| Формат | Одразу до рішення: рушій грає попередні вулиці за правильною лінією, герой робить одне рішення, вердикт, наступний спот |
| Захист від автопілота | 50/50: спот патерну проти контрастного — та сама вулиця й тип ситуації, але правильна дія інша |
| Вибір патерну | Автоматичний мікс відкритих патернів, зважений за кількістю помилок |
| Вихід патерну | 8 правильних поспіль на спотах патерну, контрасти рахуються. Помилка на контрасті скидає серію |
| Пул | Патерн у пулі, якщо після його останнього закриття є ≥ 2 помилки цього патерну у **звичайній** грі. Одне правило дає і вхід, і повернення |
| Журнал | Кожне drill-рішення — рядок `postflop_attempts` з `is_drill = true` і `drill_fix`. Авторозіграні вулиці не пишуться: там рішення приймав рушій |
| Статистика | Зрізи, total, рекорд — лише звичайні роздачі. Розбір бачить усі помилки, пул — лише звичайні |
| Стан drill | Виводиться з подій сервера: хвіст drill-відповідей → серії й закриття рахує engine. Телефон і десктоп бачать одне |
| UI | `DrillBar`-подібна плашка на TrainPost; вердикт — звичайний плюс правило патерну з `POST_FIX`, на контрасті — пояснення, що це контроль |

**Чому 8, а не 5, як у префлопі.** При 50/50 серію з 5 можна вгадати з
імовірністю ~3%, з 8 — ~0.4%.

## 2. Коли спот належить патерну

Окремої таблиці «де можливий патерн» немає: вона виводиться з
`classifyPostMistake`, інакше класифікатор і drill розійшлися б (та сама
причина, з якої таблиці правил генеруються з матриць).

- **Спот патерну F:** існує неправильна дія з доступних, яку класифікатор
  відніс би до F.
- **Арена F:** пари (вулиця, «ставки немає / є»), на яких F узагалі буває.
  Рахується перебором усіх входів класифікатора.
- **Правильні дії F:** ті `correct`, за яких F буває.
- **Контраст F:** спот на арені F, де правильна дія не з множини F. Наприклад,
  для «Блефу рівера» (правильно — чек) контраст — рівер без ставки з
  вальюю-рукою, де правильно ставити.

## 3. Генерація

Перебір: роздаємо епізод (сценарій випадковий), прокручуємо рішення героя
за правильною дією, доки не трапиться потрібний спот. Ліміт — 400 роздач;
якщо не вклались, беремо інший патерн із пулу. Тест заміряє, що кожен
патерн і кожен контраст знаходиться в межах ліміту.

## 4. Дані

Міграція `postflop_drill`:

- `postflop_attempts.is_drill boolean not null default false`,
  `drill_fix text`, обмеження `is_drill = (drill_fix is not null)`.
- `postflop_totals`, `postflop_summary` рахують лише `not is_drill`.
- `postflop_mistakes` додатково віддає `is_drill`.
- `postflop_drill_tail(max_rows)` — хвіст drill-відповідей
  (`drill_fix`, `is_correct`, `answered_at`) після мітки скидання.

Локально `PostProgress` отримує `drillLog`, записи `log` — прапор `d`.
`progressStore` переходить на версію 3 (дописує порожній `drillLog`).

## 5. Поза скоупом

Ручний вибір патерну з розбору, власні тексти контрастів для кожного
патерну, ворота на постфлопі.
