# Тести бази

RLS — головна поверхня безпеки цього застосунку. Anon-ключ публічний і лежить
у бандлі; єдине, що не дає одному користувачеві прочитати чужий журнал, — це
політики в `supabase/migrations`. Тому вони перевіряються окремим набором
інтеграційних тестів, які ганяються проти справжнього локального стека.

Ці тести **не входять** у `npm test`: вони вимагають запущеного Docker і
Supabase. Юніт-тести engine мають лишатись такими, що ганяються будь-де.

```bash
npm run db:start     # підняти локальний стек (перший запуск тягне образи)
npm run test:db      # інтеграційні тести RLS і SQL-функцій
npm run db:stop
```

Що саме перевіряється:

- користувач бачить лише свої спроби і не бачить чужих;
- користувач не може вставити рядок від імені іншого користувача;
- журнал незмінний: UPDATE і DELETE заборонені навіть власнику;
- анонім не читає і не пише нічого;
- повторний батч з тими самими `client_id` не створює дублів;
- SQL-функції рахують у межах свого користувача і не течуть між сценаріями.
