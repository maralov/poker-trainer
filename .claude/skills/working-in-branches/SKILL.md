# Робота в гілках

`main` — це прод. Vercel деплоїть кожен push у `main` автоматично, тож
`git push origin main` — не «зберегти роботу», а «викотити користувачам».
Тому кожна фіча і кожен фікс живуть у власній гілці, а `main` лишається тим,
що не соромно показати.

## Перед першим редагуванням

Перевір, де ти стоїш, — `git status` показує гілку першим рядком.

| Де ти | Що робити |
|---|---|
| `main` | Створити гілку: `git switch -c <тип>/<опис> main` |
| Чужа тематична гілка | Створити свою від `main` — не дописувати в чужу тему |
| Своя гілка з тієї ж теми | Працювати тут |

Гілку називай `<тип>/<kebab-опис>`: `fix/ranges-legend`,
`layout/single-screen-train`, `chore/branch-workflow-skill`.

## Стейджити тільки своє

**Ніколи `git add -A` і `git add .`.** У цьому репо в робочому дереві часто
лежить паралельна незакомічена робота — з іншої сесії або з іншого редактора.
`add -A` замітає її у твій коміт під твоїм повідомленням.

Став файли поіменно: `git add web/src/pages/Ranges.tsx`. Якщо у файлі є і
твої, і чужі зміни, візьми лише свої хунки — витягни потрібний хунк із
`git diff <файл>` і застосуй через `git apply --cached`.

Перед комітом завжди дивись `git diff --cached --stat`: у списку має бути
рівно те, що ти правив, і нічого більше.

## Коміт

Формат — з `CLAUDE.md`: `phase-N: короткий опис`; поза фазами вживані
`fix:`, `docs:`, `chore:`. Тіло українською пояснює *чому*.

Комітити й пушити — лише коли користувач попросив.

## Червоні прапорці

| Думка | Реальність |
|---|---|
| «Я вже на якійсь гілці, зійде» | Гілка має тему. Фікс легенди в гілці про лейаут — це чужа гілка. |
| «`add -A` швидше» | Швидше рівно доти, доки не заміте чужу роботу. Сталося. |
| «Це дрібниця, можна в `main`» | Дрібниця в `main` — це деплой у прод. Розміру змін це не питає. |
| «Потім розкладу по гілках» | Розкладати доведеться `reset` і `apply -R` по живому робочому дереву. |

## Якщо коміт уже ліг не туди

Поки не запушено — це поправно, але спершу **зроби бекап незакомічених
файлів** (вони ніде більше не існують):

```
git branch <правильна-гілка>          # зберегти коміт
git reset --soft <база>               # відмотати гілку
git restore --staged .
git show <коміт> -- <файли> | git apply -R   # прибрати свої хунки з дерева
```

Після цього звір робоче дерево з бекапом: чужі файли мають лишитись
байт-у-байт.
